## Current Conversational Writing And Recall Ownership

- `CreatorConversationWorkspace.tsx` is the canonical `/creator/editor` presentation owner. It owns the focused top bar, one sticky composer, responsive timeline/recall layout, and the mobile default-collapsed recall behavior.
- `CreatorConversationWorkspace.tsx` also owns the route-level Agent readiness marker. It exposes `restoring`, `busy`, or `ready`; the public manifest points only to the exact ready selector. Restoration disables every writing-desk action that can change conversation, recall, local prose/state, publish handoff, or chapter progression, while `CreatorHistoricalStateReview.tsx` consumes the same disabled boundary for its high-risk decisions.
- `CreatorConversationTimeline.tsx` owns one-question-per-turn intent discovery, distinct path choice, candidate-first manuscript adoption, evidence-backed local repair, human-confirmed canon UI, and the explained disabled state for a blocked next-chapter action. It cannot decide quality readiness, persist local records, call cloud facades, or publish.
- `nextChapterQualityGate.ts` is the pure domain owner for next-chapter readiness. It blocks an unconfirmed chapter, an unresolved repair decision, an active hard literary block, or a deterministic violation; an author-resolved advisory finding alone does not block progression.
- `creatorEditorNextChapterService.ts` re-evaluates the same quality gate before any draft persistence or next-canon creation. Its replaceable side-effect ports exist only for runtime isolation tests; `creator-next-chapter-service.ts` proves blocked flows perform zero draft saves, zero Canon reads, and zero Canon writes. `CreatorEditorRoute.tsx` may present the result and invoke the service, but it cannot bypass or rebuild the decision.
- `CreatorRecallRail.tsx` owns grouped recall selection, why-now/source/locator disclosure, selected count, and context-share feedback. It cannot invent memory or mutate prose/canon.
- `creatorEditorRecallViewModels.ts` is the pure adapter from real same-work chapters, local setting assets, and the linked External Echo into recall candidates. No production fixture source is allowed.
- `creatorEditorLocalChapterMemoryService.ts` owns committed cross-chapter memory projection. It may describe the author-selected path, but causal results and promises must come only from committed, evidence-locatable Canon Patch operations; candidate `projectedEffects` can never become recalled facts. Intent-derived starting conditions, target changes, required choices, expected costs, and unresolved requirements remain explicitly labelled `创作约束`. Only committed Patch values for `recentChoice` and `paidCost` may replace their intent counterparts and receive `正史` labels. Its bounded summary reserves a separate accepted-manuscript ending-evidence budget so long planning copy cannot truncate the chapter handoff. If that ending evidence exceeds the budget, the service retains the actual manuscript tail and prefixes an ellipsis; it cannot keep the front of a trailing window while dropping the final accepted paragraph. It also preserves the latest `fulfilled` or removed promise/foreshadowing path as an internal terminal tombstone; `creatorEditorRecallViewModels.ts` consumes that tombstone before hiding it, preventing an older unresolved card from returning while still allowing a later explicit Canon reopen. A cumulative `LocalCanonStateRecord` may synthesize only fulfilled tombstones for legacy suppression when its Patch is unavailable; active visible recall remains Patch-owned. Every historical chapter summary is a chapter-end snapshot, declares current Canon authoritative, and marks the selected candidate path as planning-only. Architect, Planner, Writer, and Auditor prompts repeat that precedence rule so historical intent or candidate text cannot become current state by wording alone.
- `creatorEditorDecisionContextAdapter.ts` is the only owner that promotes author-selected recall items into `CreationContextSource.manifest` with `manual_recall:<group>` reasons.
- `creatorEditorConversationSettingService.ts` is the deterministic local-only detour from explicit `设定/人物/地点/时间线/规则/伏笔` conversation prefixes into the existing local setting-asset repository. Ordinary prose must remain ordinary conversation.
- `CreatorEditorManuscriptStage.tsx`, the old rail compositions, and old workspace panels remain compatibility/test owners only; they are not the canonical route presentation and must not be imported back into `CreatorEditorRoute.tsx`.
