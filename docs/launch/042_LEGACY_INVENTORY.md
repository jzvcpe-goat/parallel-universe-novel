# Legacy Inventory

Date: 2026-07-03

Inventory policy: this is not a deletion list. It is a classification list. Anything not classified here must not be reused in Creator Pivot V2.

## Epic Ownership

This inventory is governed by Epic 0 and executed through Epic 1. Epics 2-4 may reuse an existing owner only after this file gives it a class, a target owner, and a gate. Backend, payment, and production work may reference public contracts but must not import Creator implementation files.

Every future inventory row should answer five questions:

1. What is the current owner?
2. Which class applies: Preserve, Extract, Adapt, Deprecate, or Delete?
3. Which epic will own the replacement?
4. Which gate prevents new leakage?
5. What evidence allows deletion?

## Classification Report

This report summarizes the current cut state. It should be updated whenever a legacy owner moves from `Adapt` to `Extract`, or from `Deprecate` to `Delete`.

| Class | Meaning For Pivot V2 | Current Gate |
| --- | --- | --- |
| Preserve | Use directly and protect with boundary gates | `check:legacy-imports`, `check:reader-non-generative` |
| Extract | Pull out reusable lower-level capability behind a V2 contract | `check:local-data-layer`, `check:agent-surface`, `check:publish-bundle-schema` |
| Adapt | Reuse only after product semantic change | `check:no-old-request-framing`, `check:creator-route-registry` |
| Deprecate | Compatibility/reference only; no new references | `check:legacy-imports`, `check:no-localstorage-outside-migration` |
| Delete | Keep retired request/publish components and hooks, prototype persistence owners, and the former workspace compatibility barrel absent after direct-owner migration | `check:slicing`, focused gates, browser QA |
