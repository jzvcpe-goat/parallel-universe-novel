# Existing Project Slicing Plan

Date: 2026-07-03

## Purpose

Cut the existing project into reusable capabilities and legacy surfaces before Creator Pivot V2 UI work continues. This prevents old request queue pages, old CSS, old `localStorage` persistence, direct publish flows, and external handoff packages from becoming the hidden foundation of the new local writing OS.

This plan is not a UI redesign brief. Its first responsibility is to keep old Creator prototype assumptions from silently flowing into the Pivot V2 product skeleton.

This workflow is pre-pivot slicing work. It can thin route files, classify legacy owners, add ownership gates, and create adapter seams, but it must not be reported as Product IA pivot completion, Local DB migration completion, Agent protocol implementation, External Echo completion, or PublishBundle implementation unless the corresponding phase gates prove those capabilities separately.

The focused Writing Desk cutover is narrower than a full Creator IA cutover. `/creator/editor` may use the new conversational surface once it preserves existing local repositories, decision state machine, candidate-first behavior, explicit canon confirmation, and PublishBundle handoff. The old multi-rail manuscript components then become compatibility owners and cannot return to the canonical route merely to satisfy a literal gate.

## Slicing Workflow

### S0. Freeze Source Of Truth

- Pin release repo as the only writable project source.
- Mark workspace, artifacts, Desktop, Downloads, and exported novel UI snippets as external/legacy.
- Require any external frontend or IF-novel import to pass ownership review.

### S1. Legacy Inventory

- Inventory each legacy owner.
- Assign `Preserve`, `Extract`, `Adapt`, `Deprecate`, or `Delete`.
- Track current references and next gate.
- Mark retained pre-Pivot delivery packets and plans as historical evidence so they cannot silently become implementation authority again.

### S2. Gates First

Add gates before refactoring:

```text
check:slicing
check:historical-reference-boundary
check:legacy-imports
check:no-old-request-framing
check:no-localstorage-outside-migration
check:no-page-local-css
check:no-raw-colors
check:agent-surface
check:publish-bundle-schema
check:pivot
```

At this stage, gates enforce classification and prevent new unclassified residues. They do not yet delete old UI.

`check:no-old-request-framing` also validates its own compatibility allowlist: every exemption must be a present `app/src` file that still contains an exact legacy marker. Current Pivot terms such as `CreatorPublishBundle` and `今日创作路径`, plus stable cloud-facade functions `listCreatorRequests` and `listCreatorPublishEvents`, are not product-framing matches. Historical documents use the separate historical-reference gate.

Publish-transition copy follows the same strangler rule. Non-route controllers, view models, services, and Agent labels use `发布包` / `发布包确认` once they operate on a real PublishBundle object. Compatibility route titles, TSX handoff controls, and stable Agent action IDs remain classified until their separately approved IA/action cutover; copy cleanup must not silently rename those contracts.

The first-round deliverable is limited to launch docs, gate scripts, root script wiring, feature flags, and the classification report inside `042_LEGACY_INVENTORY.md`. New UI pages, screenshots, or visual polish do not count as S0-S2 completion.

### S3. Extract Shell And Route Registry

- Extract Creator shell and navigation from `LocalCreatorApp.tsx`.
- Replace old navigation labels with V2 route registry.
- Keep old routes behind registry-owned compatibility aliases until S8/S9. Runtime feature-flag cutover requires a separately approved Epic 4 owner and tests.
- Pivot target routes (`/creator/echo`, `/creator/inspiration`, `/creator/library`, `/creator/write`, `/creator/bundles`, `/creator/workspace`) must resolve to current legacy-compatible routes until their dedicated V2 surfaces are intentionally shipped.

### S4. Extract Local Data Layer

- Move draft/settings persistence out of `localStorage`.
- Add migration-only legacy readers.
- Make IndexedDB/Dexie the canonical local store.
- Keep local creator client identity and display preferences in the active local repository. Historical tool-setting summaries remain read-only migration/cleanup data.
- Add local repository entrypoints for creative reminders, publish bundles, publish receipts, and agent operation logs before UI pages depend on them.
- Route PublishBundle and receipt reads/writes through `creatorLocalPublishRepository.ts`; feature adapters and pages must not call the generic record helpers directly.
- Route working-agent operation-log reads/writes through `creatorLocalAgentRepository.ts`; agent surfaces must not call the generic record helpers directly.
- Keep workspace backup/export aggregation in `creatorLocalWorkspaceRepository.ts`; route services call the local owner directly and `pmfSupabase.ts` exposes no workspace compatibility wrapper.

### S5. Extract Agent Surface

- Add manifest-driven action surface.
- Mark actions with risk levels and author confirmation rules.
- Make DOM action targets stable for working agents.
- Record visible agent actions in the local operation log without creating cloud jobs.

### S6. Strangle Requests Into Echo

- Keep Reader requests as an input.
- Stop making request queue the center of Creator.
- Convert request cards into External Echo and CreativeReminder candidates.
- Make `CreatorEchoQueueCard.tsx`, `CreatorEchoStatusStrip.tsx`, `CreatorEchoDecisionPanels.tsx`, and `CreatorEchoWritingRail.tsx` the direct shadcn implementation owners. `CreatorEchoPanels.tsx` is the active aggregate export. After registry, page contracts, active imports, CSS hooks, build, and browser QA migrate, delete the four obsolete `CreatorRequest*` component paths and make their absence a gate.

### S7. Bundle-First Publish

- Make publish bundle the object authors review.
- Make `CreatorPublishBundleContextPanel.tsx`, `CreatorPublishBundleImpactStrip.tsx`, and `CreatorPublishBundleReviewPanel.tsx` the direct shadcn implementation owners. `CreatorPublishBundlePanels.tsx` is the active aggregate export. After registry, contracts, DOM hooks, build, and authenticated browser evidence migrate, delete the three obsolete `CreatorPublish*` component paths and make their absence a gate.
- Keep direct Supabase publish as legacy adapter until bundle path is proven.
- Record receipts after publish.
- Persist local bundle and receipt records through the local repository.

### S8. UI Atomic Refactor

- Replace page-local markup with component contracts.
- Preserve shadcn/Radix primitives.
- Use semantic tokens and LiquidGlass variants only through the design system.
- Keep route controllers narrow: `creatorEditorRouteController.ts` is limited to route seed parsing, draft/request/branch recovery decisions, initial view-model construction, and pure selection/resolution. Command execution, shortcut behavior, browser event binding, review-fix routing, draft action flow, draft persistence, and PublishBundleDraft handoff persistence belong in dedicated controllers, services, or adapters. Any future autosave milestone must add a real consumed owner with persistence/recovery tests rather than a disabled placeholder.
- Route seed parsing is now concrete ownership: `readCreatorEditorRouteQuery(search)` in `creatorEditorRouteController.ts` parses request, draft, work, and branch keys. `CreatorEditorRoute.tsx` passes `location.search` through `useMemo` and must not construct `URLSearchParams` or read those four keys directly.
- Creator shell candidate-option semantics belong to `creatorCommandCandidateService.ts`: `resolveCommandCandidateOption(label)` owns apply-mode selection, cancellation labels, and cancellation feedback. `CreatorAppFrame.tsx` applies the typed decision, records cancellation/apply flows, and dispatches accepted editor events without rebuilding those product rules.
- Local Workspace view-model API ownership is narrow: `CreatorSettingsRouteViewModelInput`, `CreatorSettingsRouteViewModel`, and the row contracts imported by component owners remain public. Workspace-summary, operation-history, and permission leaf shapes are owner-private because no route, component, registry, Agent surface, or test imports them.

### S9. Delete Old Code

- Delete deprecated files only after gates prove no imports, no public copy residue, and no route dependency.
- Do not delete historical docs or evidence; mark them archived.
