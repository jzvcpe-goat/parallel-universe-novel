# Creator Component State Matrix

Scope: Local Creator App shared components under `app/src/components/creator`.

The goal is not to force every structural component to own every state. The goal
is to prove that every Creator component either exposes the state it is
responsible for or delegates state to a parent/page-level contract.

## Page-Level State Ownership

Some states are intentionally page-owned because they depend on data wrappers
and route context:

- Request queue loading, empty, filters, and action failures live in
  `RequestsPage`.
- Draft save/publish handoff loading and validation live in `EditorPage`.
- Publish gates, confirmation, success summary, and failure recovery live in
  `PublishCheckPage`.
- Work notice, hide, archive, and IF branch creation states live in `WorksPage`.
- Local preference save/reset, reduced motion, and reduced transparency states
  live in `CreatorSettingsRoute`; model/provider setup has no product owner.

## Regression Rules

1. New Creator components must be added to this matrix before they are used in
   production Creator routes.
2. If a component owns an action, it must expose loading and disabled states.
3. If a component owns a destructive or public-write action, it must use
   `ConfirmActionDialog` or another shadcn/Radix confirmation primitive.
4. Structural components may delegate loading, empty, error, and success states
   to page content, but that delegation must be named in this matrix.
5. Product UI copy must stay product-facing; implementation terms remain in docs
   and tests only.
